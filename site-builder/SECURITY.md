# Безопасность: перечень найденных проблем и исправлений

Аудит кода выполнен 4 ноября 2026 (просмотр кода, поиск опасных конструкций, автотесты `tests/security.test.mjs`).
Не проводились: тест на проникновение живого сайта, проверка заголовков в реальном браузере, сканирование зависимостей.

## Исправлено в коде

| № | Проблема | Риск | Что сделано | Проверка |
|---|---|---|---|---|
| 1 | При внутренней ошибке клиенту уходил текст исключения | средний: раскрытие внутренностей | клиент получает только `{"error":"server"}`, подробности в журнале воркера | тест «ошибка сервера не раскрывает внутренности» |
| 2 | Публичная форма читала тело запроса целиком, потом проверяла размер | средний: нагрузка большим телом | размер проверяется по `content-length` до чтения | тест «большое тело отклоняется» |
| 3 | Каталог кэшировался по полному адресу: `?a=1`, `?a=2` обходили кэш и нагружали базу | средний: исчерпание лимита чтений D1 | ключ кэша без строки запроса | тест «строка запроса не обходит кэш» |
| 4 | Не было защиты от встраивания страниц в чужой сайт и других заголовков | средний: кликджекинг редактора | `X-Frame-Options: DENY`, CSP `frame-ancestors 'none'; base-uri 'none'; object-src 'none'; form-action 'self'`, `Referrer-Policy`, `Permissions-Policy`; для редактора `Referrer-Policy: no-referrer` (секретный путь не уходит в Referer) | тест «заголовки безопасности» |
| 5 | Перебор пароля админки без ограничений; сравнение секрета зависело от длины | высокий при слабом пароле | блокировка адреса после 8 неудач за 10 минут (429); сравнение через SHA-256 без утечки длины и времени | тесты «перебор пароля», «сравнение секретов» |
| 6 | Пропорция карточки витрины попадала в `style` без проверки | низкий (вставка CSS, доступна только админу) | допускается только вид `число/число` | тест «витрина: пропорция фильтруются» |
| 7 | Загруженный файл при прямом открытии мог исполниться, если тип подменён | низкий (загрузка только админом) | `CSP: default-src 'none'; sandbox`, `nosniff`, SVG запрещён | проверка заголовков |
| 8 | Персональные данные (заявки) хранились бессрочно без инструмента очистки | средний (GDPR) | `DELETE /api/admin/submissions?olderThanDays=N` | тест «очистка старых заявок» |

Проверено и признано безопасным: все запросы к базе идут через подстановку параметров (конкатенации SQL нет); весь пользовательский текст на страницах и в редакторе экранируется (в `innerHTML` попадают только экранированная разметка и константы); ссылки фильтруются (`javascript:` и `//host` отбрасываются), цвета и числа приводятся к безопасному виду; словарь переводов в странице не может закрыть тег `<script>`; письма защищены от внедрения заголовков; серверные запросы идут только на фиксированные адреса (Turnstile, Resend); токен передаётся в заголовке, а не в адресе или cookie, поэтому CSRF неприменим.

## Не закрыто: нужны ваши действия или решения

| № | Остаточный риск | Серьёзность | Что сделать |
|---|---|---|---|
| A | Слабый или утёкший `ADMIN_TOKEN`: кто знает токен, может опубликовать любой HTML (сайт целиком) | высокая | токен не короче 32 случайных символов (`openssl rand -base64 32`), хранить только как секрет; менять при подозрении; разумно поставить **Cloudflare Access** (бесплатно до 50 человек) перед `/s/*` и `/api/admin/*` |
| B | Блокировка перебора работает по адресу: распределённый перебор не остановит | средняя | Cloudflare Access или правило Rate Limiting на `/api/admin/*` |
| C | Публичная форма без капчи: спам и исчерпание лимита записей D1 (100 тыс. в сутки) | средняя | включить Turnstile (секрет и ключ); правило Rate Limiting на `/api/submit`. Принудительного «капча обязательна» в коде нет |
| D | Строгая CSP работает пока только как Report-Only (чтобы не сломать сайт вслепую) | низкая | открыть сайт и редактор с консолью браузера, убедиться, что нарушений нет, затем перенести политику в `content-security-policy` |
| E | Редактор не может иметь строгую CSP: «Просмотр» открывает страницу из `blob:` со встроенным скриптом | низкая | принятое ограничение; защита держится на экранировании и на отсутствии чужого HTML в редакторе |
| F | Токен лежит в `sessionStorage` редактора: XSS в редакторе его украдёт | низкая (XSS не найдено) | не открывать в том же браузере недоверенные сайты под этим доменом; держать код редактора без сторонних скриптов |
| G | Тип загружаемого файла берётся из заголовка запроса; сигнатуры файла и антивирусной проверки нет | низкая (загрузка только админом) | загружать только свои файлы |
| H | Персональные данные: нет автоматического срока хранения, нет кнопки очистки в интерфейсе, нет выгрузки по запросу субъекта | средняя | настроить срок хранения (вызов очистки вручную или по расписанию), добавить на сайт политику конфиденциальности и ссылку в согласии, договор с почтовым сервисом (Resend) |
| I | Нет журнала действий администратора | низкая | при нескольких редакторах добавить; сейчас редактор один |
| J | Письма: подлинность отправителя зависит от DNS вашего домена | средняя | настроить SPF, DKIM, DMARC у домена `NOTIFY_FROM` |
| K | Резервные копии D1 и R2 не настроены | средняя (доступность) | регулярно выгружать `wrangler d1 export`; не хранить единственную копию медиа только в R2 |
| L | Лимит 5 заявок за 10 минут проверяется без блокировки (при одновременных запросах возможен небольшой перебор) | низкая | принято |
| M | Cloudflare-настройки домена: HTTPS всегда, HSTS, Bot Fight Mode, отключение `workers.dev`, если домен свой | средняя | включить в панели Cloudflare |
